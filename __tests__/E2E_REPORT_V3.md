## 1. E2E 自动化可行性评估（结论：不可行）

### 1.1 环境约束

本项目为**微信小程序原生框架**（WXML + WXSS + JS），运行于微信客户端封闭运行时，**无法用 Playwright/Cypress 等浏览器自动化工具驱动**：

| 维度 | 浏览器 Web 应用 | 微信小程序（本项目） |
|------|----------------|---------------------|
| DOM/WXSS | 标准 DOM，可定位 | WXSS 虚拟 DOM，外部不可见 |
| 自动化工具 | Playwright/Cypress/Selenium | ❌ 均不支持 |
| 网络层 | 可拦截 fetch/XHR | 仅 `wx.request`，需真机/开发者工具 |
| 运行时 | Node/浏览器 | 微信 JS Bridge（`wx.*` API） |

### 1.2 替代策略

采用 **「单元测试 + 集成测试 + 云函数联调」三层 + 手动测试清单** 替代 E2E：

- **可自动化层**：common 模块（纯逻辑）、云函数（Mock wx-server-sdk）—— 已覆盖 1372 断言 + 118 联调
- **手动层**：小程序页面交互、真机支付、会员订阅 —— 本文档清单

> 微信官方提供 [miniprogram-automator](https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/) 可在开发者工具中自动化，但需真机/IDE 环境，**不适合 CI**，列为后续可选项（见 §4）。

## 2. 手动 E2E 测试清单（按优先级）

### P0 — 计费与额度（近期 P1 修复，必测）

对应模块：`quota-service.js` / `createOrder` / `generateAIReport` / `payCallback`

| # | 场景 | 步骤 | 预期 |
|---|------|------|------|
| E1 | 新用户首份优惠 | 新 openid → 首次生成报告 | 价格 ¥1.00（FIRST_REPORT），扣减后 first_report_used=true |
| E2 | 首份防绕过 | 删号重注册 → 再次生成 | **不应**再次享 ¥1.00（ORDERS 交叉验证），回退标准价 |
| E3 | 邀请奖励额度 | 邀请 3 人获奖励 → 生成报告 | 免费，invite_reward_credits 递减 |
| E4 | 会员额度月度重置 | 月卡用满 → 跨重置日再生成 | 自动重置 report_credits_used=0，可再用 |
| E5 | 会员额度扣减原子性 | 并发点两次「生成报告」 | 仅成功 1 次（条件更新 `_.lt(total)`），另一次回退付费 |
| E6 | 订单失败额度回滚 | 创建订单失败 | rollbackQuota 恢复额度（首份/邀请/会员/点数）|
| E7 | 点数包扣减 + 流水 | 点数余额生成报告 | balance-1，POINT_TRANSACTIONS 写入 consume 流水 |

### P0 — 支付回调（近期日志脱敏修复）

对应模块：`payCallback` / 支付日志

| # | 场景 | 预期 |
|---|------|------|
| E8 | 真实支付回调 | 支付成功 → 会员/点数到账，日志中 token/openid/密钥已脱敏（`***`）|

### P1 — 食物安全搜索（近期正则/分页/鉴权修复）

对应模块：`searchFoodSafety`

| # | 场景 | 预期 |
|---|------|------|
| E11 | 关键词搜索 | 输入「葡萄」→ 命中 name/aliases，severity 倒序 |
| E12 | 正则注入防御 | 输入 `a.*+?^${}()|[]\` → 不报错、不卡顿（无 ReDoS）|

## 3. E2E 缺陷严重级分类

| 级别 | 定义 | 示例 |
|------|------|------|
| 🔴 致命 | 计费错误/资损/无法登录 | E2 首份绕过、E5 重复扣减、E8 回调不发券 |
| 🟠 严重 | 核心功能不可用 | E18 报告生成全失败、E16 全员游客态 |
| 🟡 一般 | 功能异常但有绕过 | E11 搜索无结果、E14 限流误触发 |
| 🔵 轻微 | 体验问题 | 文案、样式、动画 |

## 4. 后续可选：miniprogram-automator 自动化

若需将部分 E2E 纳入 CI，可引入微信官方 `miniprogram-automator`：
- 前置：微信开发者工具 + CLI（需 GUI 环境，CI 需额外配置）
- 适用：E16-E20 页面级冒烟（登录、宠物、症状提交）
- 不适用：真实支付（需商户号/真机）
- 建议：仅作为发布前手动触发的 smoke gate，不阻断每次提交

## 5. 本轮 E2E 结论

- 自动化 E2E：❌ 不可行（环境约束）
- 手动清单：✅ 20 项（P0×10 / P1×5 / P2×5），发布前必跑 P0
- 自动化补偿：✅ 计费/搜索/鉴权核心逻辑已由 1372 单元断言 + 118 联调覆盖
