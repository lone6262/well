# 一、提交（用户动作）

# 1.1 触发条件

用户完成以下步骤后，点击 “提交评估” 按钮： 

已选择宠物（若未选择，提示“请先选择宠物”） 

 已勾选至少 1 个症状（若未勾选，提示“请至少选择一个症状”） 

 补充描述（选填）字数 ≤ 100 字，且不含敏感词 

# 1.2 提交动作

按钮状态：点击后变为 加载中...， 禁用重复点击 

调用云函数：submitSymptom 

 入参： json { "petId": "pet_001", "symptomIds": ["vomit", "diarrhea", "lethargy"], "description": "呕吐物为白色泡沫，精神萎靡" } 

# 1.3 前端等待

 显示加载提示：“正在评估风险，请稍候...” 

超时设置：5 秒未返回结果，提示“网络繁忙，请重试” 

# 二、规则引擎判断风险等级（云函数内部）

# 2.1 输入数据

字段 说明 

petId 宠物 ID，用于后续记录 

symptomIds 用户勾选的症状 ID 列表（数组） 

description 用户补充文本（可选） 

# 2.2 规则引擎逻辑（纯规则，无 AI）

# 第一步：高风险判断（熔断检查）

若 symptomIds 中包含以下 高危症状 ID 中的任意一个，直接判定为 高风险： 

症状 ID 对应症状 

seizure 抽搐 

coma 昏迷 

dyspnea 呼吸困难 

bleeding 持续出血 

hematuria 尿血 

paralysis 瘫痪 

→ 判定结果：riskLevel = "high"，不进行后续判断，直接返回。 

# 第二步：中风险判断（未触发高风险时）

若满足以下 任一条件，判定为 中风险： 

条件 说明 

条件 A 症状数量 ≥ 3 个，且包含 vomit（呕吐）或 diarrhea（腹泻）或 fever（发热） 

条件 B 症状数量 ≥ 3 个，且用户补充描述中包含“反复”“持续”“加重”等关键词 

条件 C 症状数量 ≥ 4 个（不考虑具体症状） 

→ 判定结果：riskLevel = "mid" 

# 第三步：低风险判断

不满足高风险和中风险条件 → riskLevel = "low" 

# 2.3 输出结果（云函数返回）

```json
json
{
    "code": 0,
    "data": {
    "recordId": "rec_001",
    "riskLevel": "mid", // "low" / "mid" / "high"
    "advice": "建议24小时内就医观察，记录症状变化", // 对应风险等级的固定建议
    "symptomSummary": "呕吐、腹泻、精神萎靡" // 用于前端展示
    }
} 
```

 只有一个按钮：“前往急救通道”

# 5.3 跳转时的数据传递

跳转时，自动传递以下参数（通过 query 或 storage）： 

```json
json

    "fromRiskResult": true,
    "riskLevel": "high",
    "petId": "pet_001"
```

# 5.4 急救通道页面行为

 自动请求定位权限 

 显示最近 3 家 24 小时急诊宠物医院 

页面顶部显示红色提示：“⚠️ 您的宠物被评估为高风险，请立即就医！” 

# 5.5 禁止操作

 高风险结果页 不允许 返回首页或重新自查（防止用户延误就医） 

若用户点击返回按钮，弹出确认框：“您的宠物为高风险，是否确认返回？” （仅用于极端情况） 

# 六、异常处理与边界场景

场景 

处理方式 

网络异常 

提交时显示“网络异常，请重试”，保留已填数据 

云函数超时（>5 秒） 

显示“评估超时，请重试”，不创建记录 

场景 

处理方式 

规则引擎无匹配 

默认降级为“低风险”，并记录异常日志 

高风险跳转后用户返回 

用户可返回结果页，但会再次提示“高风险，请立即就医” 

用户拒绝定位 

急救通道显示“请授权定位”，否则无法显示医院
