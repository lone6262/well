## 1. 项目简介

### 1.1 项目背景

宠物症状自查小程序是一款面向宠物主人的健康管理工具，帮助用户快速评估宠物症状的紧急程度，并提供就近宠物医院推荐与导航服务。

### 1.2 目标用户

- 养猫/养狗的宠物主人
- 需要快速判断宠物症状紧急程度的用户
- 需要查找附近宠物医院的用户

### 1.3 核心价值

| 能力 | 描述 |
|------|------|
| **症状自查** | 基于规则引擎的风险评估，3步完成症状自查 |
| **风险评估** | 三级风险（高/中/低）自动分级，匹配对应处理建议 |
| **急救通道** | GPS定位 + 24小时急诊医院优先推荐 |
| **宠物档案** | 完整的宠物CRUD管理，含头像上传、健康状态追踪 |
| **医院导航** | 对接腾讯地图API，一键导航到最近的宠物医院 |

### 1.4 技术栈

| 层级 | 技术 |
|------|------|
| 前端 | 微信小程序原生框架（WXML / WXSS / JS） |
| 后端 | 微信云开发（Cloud Functions + Cloud Database） |
| 地图 | 腾讯地图 WebService API（服务端调用） |
| 存储 | 微信云存储（头像、图片） |
| 登录 | 微信静默登录 + 按需授权 |

```
用户操作 → 页面JS → wx.cloud.callFunction → 云函数 → 云数据库
                                    ↓
                              腾讯地图API（仅searchHospitals）
                                    ↓
                              返回结果 → 页面渲染
```

### 3.3 降级策略

```
云开发可用？
  ├── 是 → 云函数 → 云数据库 → 返回真实数据
  └── 否 → 本地模拟数据 / localStorage 降级
            ├── 宠物列表 → wx.getStorageSync('localPets')
            ├── 医院数据 → 离线推荐数据
            ├── 登录状态 → mock openid
            └── 自查记录 → 本地存储
```

## 5. 详细业务流程

### 5.1 用户登录流程

```
小程序启动 (onLaunch)
  │
  ├── 恢复本地登录状态 (openid/token/userInfo)
  │
  ├── 初始化云开发 (wx.cloud.init)
  │     ├── 成功 → 标记 cloudDevelopmentAvailable = true
  │     └── 失败 → 标记 cloudDevelopmentAvailable = false
  │
  ├── 云开发可用？
  │     ├── 是 → wx.login() 获取 code
  │     │         │
  │     │         └── 调用 silentLogin 云函数
  │     │               ├── 成功 → 保存 openid/token/userInfo
  │     │               │         通知等待页面
  │     │               └── 失败 → 创建 mock 用户（降级）
  │     │
  │     └── 否 → 创建 mock 用户
  │               使用 localPets 本地存储
  │
  └── 检查首次启动 → 显示免责声明
```

### 5.2 症状自查流程

```
用户点击「症状自查」Tab
  │
  ├── 步骤1：选择宠物
  │     ├── 从 getPetList 获取宠物列表
  │     ├── 用户点击选中一只宠物
  │     └── 若无宠物 → 引导添加宠物
  │
  ├── 步骤2：选择症状
  │     ├── 8大分类平铺展示（消化、呼吸、皮肤、眼耳、行为、泌尿、神经、全身）
  │     ├── 每个分类下多个症状可多选
  │     ├── 底部显示已选标签（可逐个移除）
  │     └── 至少选择1个症状才能进入下一步
  │
  ├── 步骤3：补充描述
  │     ├── 文本描述（300字限制，含敏感词过滤）
  │     ├── 持续时间选择（急性/慢性）
  │     └── 严重程度（轻微/中度/严重）
  │
  └── 提交评估
        ├── 调用 submitSymptom 云函数
        │     ├── 规则引擎三步评估
        │     │     ├── 高风险熔断（抽搐/昏迷/呼吸困难等8种）
        │     │     ├── 中风险条件（4条规则）
        │     │     └── 默认低风险
        │     └── 保存评估记录到 symptom_records
        │
        └── 跳转结果页
              ├── 高风险 → 建议立即就医 → 可跳转急救通道
              ├── 中风险 → 建议24小时内就医 → 可查看医院列表
              └── 低风险 → 建议继续观察 → 返回首页
```

### 5.3 宠物档案管理流程

```
用户点击宠物卡片 / 添加按钮
  │
  ├── 新增宠物
  │     ├── 填写表单（名称*、类型*、年龄*、品种、体重、性别）
  │     ├── 可选上传头像（拍照/相册，≤5MB，建议500×500）
  │     ├── 表单校验
  │     └── 保存
  │           ├── 云开发可用 → savePet 云函数
  │           │     ├── 自动生成宠物编号（CAT-001 / DOG-001）
  │           │     ├── 保存到 pets 集合
  │           │     └── 返回结果
  │           └── 云开发不可用 → 保存到 localPets 本地存储
  │
  ├── 编辑宠物
  │     ├── 回填已有数据到表单
  │     ├── 修改后保存（同新增流程）
  │     └── 支持 avatar 更换/删除
  │
  ├── 删除宠物
  │     ├── 二次确认弹窗
  │     ├── 云开发可用 → deletePet 云函数（级联删除 symptom_records）
  │     └── 云开发不可用 → 从 localPets 中移除
  │
  └── 查看记录
        ├── 点击「自查记录」→ 调用 getRecordList，按宠物ID筛选
        ├── 点击「健康报告」→ 同上
        └── 点击记录条目 → 跳转风险评估详情页
```

### 5.4 急救通道流程

```
用户点击「急救」Tab
  │
  ├── 获取用户位置 (wx.getLocation)
  │     ├── 成功 → 使用真实坐标
  │     └── 失败 → 使用默认坐标（北京天安门）
  │
  ├── 加载急救医院
  │     ├── 云开发可用 → searchHospitals 云函数
  │     │     ├── 并行搜索多个关键词
  │     │     ├── 去重 + 排序（24h优先 → 距离近 → 搜索优先级）
  │     │     └── 返回医院列表
  │     └── 云开发不可用 → 使用离线推荐数据
  │
  ├── 展示最近医院（卡片突出显示）
  │     ├── 医院名称、距离、地址、电话
  │     ├── 「立即拨打」按钮
  │     └── 「导航」按钮
  │
  ├── 拨打电话
```

## 6. 核心功能模块详解

### 6.1 登录与认证模块

**文件**：`app.js` + `cloudfunctions/silentLogin/`

| 特性 | 说明 |
|------|------|
| 静默登录 | 启动时自动完成，用户无感知 |
| Token机制 | HMAC-SHA256签名，7天有效期 |
| 状态恢复 | 每次启动从 localStorage 恢复登录态 |
| 降级方案 | 云开发不可用时自动创建 mock openid |
| 按需授权 | 仅在需要用户资料时调用 getUserProfile |
| 回调队列 | 页面通过 `app.onLoginComplete()` 注册回调 |

**登录状态流转**：
```
启动 → restoreLoginState() → _initCloudAsync() → _silentLoginAsync()
 → 成功：openid + token + userInfo → _notifyLoginComplete()
 → 失败：createMockUser() / simulatedLogin() → 降级模式
```

### 6.2 规则引擎模块

**文件**：`cloudfunctions/submitSymptom/index.js`

规则引擎采用三步判断法，优先级从高到低：

| 步骤 | 规则 | 风险等级 | 建议行动 |
|------|------|----------|----------|
| 1. 高风险熔断 | 症状包含抽搐/昏迷/呼吸困难/持续出血/尿血/瘫痪/虚脱/发绀（8种） | **HIGH** | 立即就医（emergency） |
| 2. 中风险条件 | R1: 症状≥3 且含呕吐/腹泻/发热 | **MID** | 24小时内就医（hospital_list） |
| | R2: 症状≥3 且描述含"反复/持续/加重"等关键词 | | |
| | R3: 症状≥4（多系统症状） | | |
| | R4: 含精神萎靡 + 其他症状≥1 | | |
| 3. 默认低风险 | 未命中以上规则 | **LOW** | 继续观察（home） |

**高风险症状清单**：
```
seizure(抽搐), coma(昏迷), dyspnea(呼吸困难), bleeding(持续出血),
hematuria(尿血), paralysis(瘫痪), collapse(虚脱), cyanosis(发绀)
```

| 分类 | 图标 | 包含症状 |

| 眼睛耳朵 | 👀 | 眼部分泌物、耳朵异味、眼睛发红、频繁甩头 |
| 行为异常 | 😟 | 精神萎靡、异常叫唤、攻击性增强、躲藏 |
| 泌尿系统 | 💧 | 尿频、尿血、排尿困难、尿失禁 |

### 6.4 地图服务模块

## 7. 数据库设计

### 7.1 集合总览

| 集合名 | 用途 | 主要消费者 |
|--------|------|------------|
| `users` | 用户信息 | login, silentLogin, saveUserProfile, getUserStats |

| `ai_cache` | AI缓存（预留） | - |

### 7.2 users 集合

```javascript
{
  _id: String,              // 系统自动生成
  openid: String,           // 微信openid（唯一标识）
  nickName: String,         // 用户昵称
  avatarUrl: String,        // 头像URL
  gender: Number,           // 性别（0未知/1男/2女）
  country: String,          // 国家
  province: String,         // 省份
  city: String,             // 城市
  isMember: Boolean,        // 是否会员
  memberExpire: Date,       // 会员过期时间
  loginCount: Number,       // 登录次数
  lastLoginAt: Date,        // 最近登录时间
  created_at: Date,         // 注册时间
  updated_at: Date          // 更新时间
}
```

### 7.3 pets 集合

```javascript
{
  _id: String,              // 系统自动生成（即petId）
  user_id: String,          // 所属用户openid
  name: String,             // 宠物昵称（必填）
  type: String,             // 类型：cat / dog / other（必填）
  breed: String,            // 品种
  age: Number,              // 年龄（月）（必填）
  weight: Number,           // 体重（kg）
  gender: String,           // 性别：male / female
  vaccine_date: String,     // 上次疫苗日期（YYYY-MM-DD）
  deworm_date: String,      // 上次驱虫日期（YYYY-MM-DD）
  avatar: String,           // 头像云存储URL
  petCode: String,          // 宠物编号（CAT-001 / DOG-001）
  created_at: Date,         // 创建时间
  updated_at: Date          // 更新时间
}
```

**字段命名规则**：云数据库使用 `snake_case`（如 `user_id`），前端展示时映射为 `camelCase`（如 `userId`），映射发生在各云函数的返回数据组装中。

### 7.4 symptom_records 集合

```javascript
{
  _id: String,              // 系统自动生成
  user_id: String,          // 用户openid
  pet_id: String,           // 宠物ID（关联 pets._id）
  symptoms: [String],       // 症状ID列表（英文，如 ["vomit","diarrhea"]）
  symptom_names: [String],  // 症状名称列表（中文，如 ["呕吐","腹泻"]）
  description: String,      // 用户描述文本
  risk_level: String,       // 风险等级：low / mid / high
  matched_rule: String,     // 匹配的规则说明
  status: String,           // 状态：completed
  action: String,           // 建议行动：home / hospital_list / emergency
  created_at: Date          // 创建时间
}
```

### 7.5 索引建议

| 集合 | 索引字段 | 类型 | 说明 |
|------|----------|------|------|
| `users` | `openid` | 唯一 | 快速查找用户 |
| `pets` | `user_id` | 普通 | 按用户查宠物列表 |
| `pets` | `user_id + petCode` | 联合唯一 | 防止编号重复 |
| `symptom_records` | `user_id` | 普通 | 按用户查记录 |
| `symptom_records` | `pet_id` | 普通 | 按宠物查记录 |
| `symptom_records` | `user_id + created_at` | 联合 | 分页查询优化 |

## 10. 版本局限与后续优化点

### 10.1 当前版本局限

| 类别 | 局限 | 影响 |
|------|------|------|
| **评估准确性** | 规则引擎为静态规则，非AI模型 | 评估结果仅供参考，无法处理复杂症状组合 |
| **医院数据** | 完全依赖腾讯地图API | API配额用尽时降级为离线数据，电话号码可能不全 |
| **用户系统** | 仅微信静默登录 | 无法跨平台，无手机号/邮箱绑定 |
| **数据同步** | 云开发不可用时仅本地存储 | 恢复云开发后本地数据不会自动同步到云端 |
| **图片处理** | 无压缩/缩略图 | 大图直接上传，可能影响加载速度 |
| **无消息推送** | 缺少疫苗/驱虫提醒 | 用户无法收到定期提醒 |
| **无分享功能** | 缺少分享到聊天/朋友圈 | 无法通过社交裂变传播 |
| **记录类型** | 自查记录和健康报告为同一数据 | 未做类型区分 |

### B. 错误处理规范

前端统一错误处理流程：
```
wx.cloud.callFunction 调用
  ├── success
  │     ├── res.result.code === 0 → 业务成功
  │     ├── res.result.code === 401 → 引导登录
  │     └── 其他 → wx.showToast 提示错误信息
  └── fail
        ├── 标记 cloudDevelopmentAvailable = false
        └── 切换到本地降级模式
```
