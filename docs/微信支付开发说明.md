## 1. 整体架构

项目用**腾讯云 CloudBase 集成中心的微信支付**能力做统一下单与回调验签解密，自研业务层负责订单、额度与履约。

```
┌──────────────┐  1. createOrder(type, ...)        ┌────────────────────┐
│  小程序前端   │ ─────────────────────────────────▶ │  createOrder 云函数 │
│ (4 个购买入口)│                                    │  建 PENDING 订单    │
└──────────────┘                                    └─────────┬──────────┘
      │ 3. wx.requestPayment(payParams)                       │ 2. cloud.callFunction
      │                                                       ▼
      │                                          ┌──────────────────────────────┐
      ▼                                          │ Mewora-1r02jkm1-demo-scfweb   │
┌──────────────┐  4. JSAPI 统一下单               │ (集成中心支付函数 / gateway)   │
│  微信支付     │ ◀────────────────────────────── │  wechatpay-node-v3            │
│  用户付款     │ ──── 5. 支付成功回调 ──────────▶ │  notify_url = 网关回调地址     │
└──────────────┘                                  └──────────────┬───────────────┘
                                                                 │ 6. 验签 + AES-GCM 解密
                                                                 │    转发明文给业务函数
                                                                 ▼
                                                  ┌──────────────────────────────┐
                                                  │ payCallback 云函数            │
                                                  │ 幂等/金额校验 → 按订单类型履约 │
                                                  │ (激活会员/到账点数/拆套餐)     │
                                                  └──────────────────────────────┘
```

**关键约定**：集成函数 `signMode=gateway`，即签名验证与回调解密由 CloudBase 网关自动完成；业务侧 `payCallback` 收到的是**明文**结果，无需自己验签解密。

### 涉及的云函数

| 云函数 | 职责 |
|--------|------|
| `createOrder` | 所有购买入口的下单：解析价格/额度、建 `PENDING` 订单、调集成函数统一下单、返回 `payParams` |
| `Mewora-1r02jkm1-demo-scfweb` | 集成中心支付函数（模板部署）：JSAPI 下单、退款；由网关验签解密回调 |
| `payCallback` | 支付结果回调入口：幂等 + 金额校验 + 按类型激活业务 |
| `generateAIReport` | AI 报告专属：先查/建订单 → 生成报告（与 createOrder 协作避免双扣） |
| `requestRefund` / `processRefund` | 用户申请退款 / 管理员执行退款 |
| `closeExpiredOrders` | 定时关闭超时未支付订单 |

## 2. 前置准备：凭证与证书

在微信支付商户平台（pay.weixin.qq.com）与微信公众平台（mp.weixin.qq.com）取得：

| 凭证 | 获取位置 | 用途 |
|------|----------|------|
| **AppID** | 微信公众平台 → 开发管理 → 开发设置 | 小程序标识 |
| **商户号 merchantId** | 商户平台 → 账户中心 → 商户信息 | 收款方 |
| **商户API证书序列号 merchantSerialNumber** | 商户平台 → API 安全 → API 证书 | 标识商户证书 |
| **商户私钥 privateKey** | 下载 API 证书，读取 `apiclient_key.pem` 全文 | 请求签名 |
| **APIv3 密钥 apiV3Key** | 商户平台 → API 安全 → API v3 密钥（自设 32 位） | 回调内容解密 |
| **微信支付公钥 wxPayPublicKey / 公钥ID** | 商户平台 → API 安全 → 平台证书/公钥 | 验证微信签名（公钥模式） |

证书包通常含：`apiclient_cert.p12`、`apiclient_cert.pem`、`apiclient_key.pem`、`pub_key.pem`。
- `apiclient_key.pem` 的全文（含 `-----BEGIN/END-----`）即 `privateKey`。
- 证书 **是敏感信息**，绝不提交 Git；本项目凭证放在云函数环境变量里（见 [§3](#3-集成支付函数配置mewora-1r02jkm1-demo-scfweb)），不落源码。

> 商户平台还要配置：**支付授权目录**（小程序无需）、**API 安全选项**（开启 V3）。

## 3. 集成支付函数配置（Mewora-1r02jkm1-demo-scfweb）

集成函数由 CloudBase 控制台「集成中心 → 微信支付」部署生成，本仓库保留其源码副本与 [cloudbaserc.json](../cloudbaserc.json) 中的配置。**修改 env 必须连同源码一起 `tcb fn deploy --force` 才会生效**。

### 3.1 环境变量

| 变量 | 示例/说明 |
|------|-----------|
| `appId` | `wxee33a0c47421db2c` |
| `merchantId` | 商户号 |
| `merchantSerialNumber` | 商户证书序列号 |
| `apiV3Key` | 32 位 APIv3 密钥 |
| `privateKey` | `apiclient_key.pem` 全文（`\n` 转义） |
| `wxPayPublicKey` / `wxPayPublicKeyId` | 微信支付公钥（公钥验签模式） |
| `signMode` | `gateway`（**网关自动验签解密**，推荐） |
| `notifyURLPayURL` | `https://Mewora-1r02jkm1.integration-callback.tcloudbase.com/wechatpay/order`（支付回调，由控制台分配） |
| `notifyURLRefundsURL` | `https://Mewora-1r02jkm1.integration-callback.tcloudbase.com/wechatpay/refund`（退款回调） |
| `notifyURLPayResourceType` | `SCF` |
| `notifyURLPayResourceName` | `payCallback`（解密后转发到的业务函数） |
| `notifyURLRefundsResourceType` | `SCF` |
| `notifyURLRefundsResourceName` | `payCallback` |

> ⚠️ **回调链关键**：`notifyURLPayURL` 必须指向**集成网关**的回调地址（`*.integration-callback.tcloudbase.com`），由网关验签解密后再转发给 `payCallback`。**不能**直接指向业务函数的 HTTP URL，否则业务侧会收到密文、无法处理。

### 3.2 下单/退款接口

集成函数内（`exports.main`）按 `event.action` 路由：

| action | 说明 |
|--------|------|
| `/wx-pay/wxpay_order` | JSAPI 小程序下单，返回 `prepay_id` + 调起参数 |
| `/wx-pay/refund` | 申请退款 |

`createOrder` 通过 `cloud.callFunction({ name: 'Mewora-1r02jkm1-demo-scfweb', data: { action, params, openid } })` 调用。

## 4. 下单流程（createOrder）

文件：[cloudfunctions/createOrder/index.js](../cloudfunctions/createOrder/index.js)

### 4.1 入口与路由

```js
exports.main = async (event, context) => {
  // Token 校验、限流、openid 校验
  // 按 event.type 路由：
  switch (orderType) {
    case 'report':          return handleReportOrder(...)
    case 'member':          return handleMemberOrder(...)
    case 'points':          return handlePointsOrder(...)
    case 'bundle':          return handleBundleOrder(...)
  }
}
```

`mockPay` 由 `system_config.wechat_pay_config.mock_pay`（DB）或环境变量 `MOCK_PAY` 决定（生产为 `false`）。

### 4.2 四种订单类型

| type | 必填参数 | 价格来源 | 履约方 |
|------|----------|----------|--------|
| `report` | `recordId` | 额度解析（首份¥1 / 会员免费 / 标准¥9.9） | generateAIReport（查单后生成） |
| `member` | `memberTier`（monthly/yearly/family_monthly/family_yearly） | `PRICES.MEMBER_*` | payCallback → activateMember |
| `points` | `packType`（PACK_3/PACK_5） | `POINTS_PACKS[packType].price` | payCallback → creditPoints |
| `bundle` | `bundleKey`（STARTER/ESSENTIAL/FAMILY） | `BUNDLES[bundleKey].price` | payCallback → processBundle（拆子单） |

### 4.3 真实模式返回的 payParams

任一类型在 `!mockPay && 金额>0` 时都会调 `createWechatPayment()` 向集成函数下单，返回给前端：

```jsonc
{
  "code": 0,
  "data": {
    "orderId": "...",
    "outTradeNo": "WELL_...",
    "status": "pending",
    "amount": 1990,                 // 分
    "amountDisplay": "19.90",
    "payParams": {                  // 交给 wx.requestPayment
      "timeStamp": "...",
      "nonceStr": "...",
      "package": "prepay_id=...",
      "signType": "RSA",
      "paySign": "..."
    }
  }
}
```

免费/0 元/mock 模式：`payParams` 为 `null`，订单已直接 `PAID`（或前端直接进入履约）。

### 4.4 createWechatPayment 内部

```js
const result = await cloud.callFunction({
  name: 'Mewora-1r02jkm1-demo-scfweb',
  data: {
    action: '/wx-pay/wxpay_order',
    params: { description, out_trade_no, amount: { total: 总价(分), currency: 'CNY' } },
    openid
  }
});
// 集成函数返回 { code:0, data:{ prepay_id, timeStamp, nonceStr, package, signType, paySign } }
```

失败回滚：下单异常时删除刚建的订单（套餐连子订单一起删），返回「支付通道暂不可用」。

## 5. 前端调起支付

### 5.1 统一封装 utils/pay.js

文件：[miniprogram/utils/pay.js](../miniprogram/utils/pay.js)

```js
const { invokePayment } = require('../../utils/pay')
invokePayment(payParams)        // → Promise
  .then(() => { /* 支付成功 */ })
  .catch(err => { /* 取消/失败 */ })
```

### 5.2 四个购买入口的统一模式

每个入口都是：**createOrder → 有 payParams 则 invokePayment → 成功后履约**。

| 入口 | 文件 | 支付成功后 |
|------|------|------------|
| 会员购买 | [member/order.js](../miniprogram/pages/member/order.js) `doPurchase` | 轮询 `getMemberStatus` 确认开通（`_pollMemberActivation`），因 payCallback 异步激活 |
| 点数包 | [points/index.js](../miniprogram/pages/points/index.js) `purchasePack` | 刷新余额（点数由 payCallback 异步到账） |
| 套餐 | [bundle/index.js](../miniprogram/pages/bundle/index.js) `onPurchaseBundle` | 跳转用户中心（会员+点数由 payCallback 异步激活） |
| AI 报告 | [risk/result.js](../miniprogram/pages/risk/result.js) `generateReport` | 支付后再调 `generateAIReport` 生成报告（见 §7） |
| 测试支付（1 分） | [member/index.js](../miniprogram/pages/member/index.js) `createTestOrder` | 验证支付链路 |

> 会员购买之所以要轮询：`wx.requestPayment` 成功只代表微信收到钱，`payCallback` 激活会员有几秒延迟。前端用 `_pollMemberActivation` 最多轮询 5 次（每次 1s）确认 `is_member=true`，超时则提示「开通中，请稍后查看」。

## 6. 支付回调与业务激活（payCallback）

文件：[cloudfunctions/payCallback/index.js](../cloudfunctions/payCallback/index.js)

### 6.1 回调链路

```
微信支付 ──▶ 网关(integration-callback) ──验签+解密──▶ payCallback(明文 event)
```

`payCallback` 收到的 event 兼容两种字段形态（网关版本可能不同）：
- V2 形态：`{ out_trade_no, transaction_id, total_fee, result_code }`
- V3 形态：`{ out_trade_no, transaction_id, amount:{total}, trade_state }`

入口处有 `console.log('[payCallback] raw event:', JSON.stringify(event))`，**首个真实回调务必看日志核对实际字段**。

### 6.2 处理步骤

1. **提取** `out_trade_no`、金额（`total_fee` ?? `amount.total`）、支付状态（兼容 `result_code`/`trade_state`）。
2. **支付失败** → `handlePaymentFailed`（订单置 `FAILED`）。
3. **查订单** → 不存在则 `FAIL`；已 `PAID` 则幂等返回 `OK`；已关闭/退款中则记对账差异。
4. **金额一致性校验**：微信金额 ≠ 订单金额 → 记 `BILL_CHECK_LOGS`，返回 `FAIL`（人工介入）。
5. **原子更新** `PENDING → PAID`（`where status=PENDING`，天然幂等防并发）。
6. **标记优惠券** used。
7. **按类型分发** `dispatchPostPayment`。
8. 埋点 + 订阅消息通知。
9. 返回 `{ errcode:0, errmsg:'OK' }`（微信/网关收到 OK 后不再重试）。

> 异常时也返回 OK 避免网关无限重试；差异订单走人工对账与补偿。

### 6.3 分发表

| order.type | 履约 |
|------------|------|
| `report` | 报告核心在 createOrder 已处理；此处仅确认（额度已在 createOrder 预扣） |
| `member` / `member_monthly` / `member_yearly` | `activateMember` |
| `member_family_monthly` / `member_family_yearly` | `activateFamilyMember` |
| `points` | `creditPoints`（读 `metadata.points_count`/`expire_days`） |
| `bundle` | `processBundle`（递归激活各子订单） |

## 7. AI 报告的额度与支付（generateAIReport）

文件：[cloudfunctions/generateAIReport/index.js](../cloudfunctions/generateAIReport/index.js)

报告的额度来源（优先级从高到低）：

| 来源 | 条件 | 价格 |
|------|------|------|
| `first_report` | 新用户首份 | ¥1.00（`PRICES.FIRST_REPORT=100`） |
| `invite` | 有邀请奖励额度 | 免费 |
| `member` | 有效会员且 `used < total` | 免费 |
| `paid` | 以上都不满足 | ¥9.90（`PRICES.STANDARD_REPORT=990`） |

### 7.1 resolveReportOrder（生成前先查单）

为避免「付费报告白送」和「createOrder 与 generateAIReport 双重扣额度」，报告生成**之前**先调 `resolveReportOrder(recordId)`：

```
查 ORDERS where type=report and metadata.record_id=recordId
├─ 有 PAID 单            → 复用 orderId，直接生成
├─ 有 PENDING 单
│   ├─ amount=0（免费）  → 标 PAID，生成
│   └─ amount>0（未支付）→ 返回 needPayment，前端先去支付
└─ 无单
    ├─ 免费来源          → 扣额度 + 建 PAID 单，生成
    └─ 付费来源          → 返回 needCreateOrder，前端先 createOrder
```

### 7.2 前端配合

[risk/result.js](../miniprogram/pages/risk/result.js) `generateReport`：
1. 先 `createOrder({type:'report', recordId})`。
2. `data.existingReportId` → 已有报告，直接看。
3. `data.payParams` → `invokePayment` → 成功后调 `generateAIReport`。
4. 无 `payParams`（免费/0 元）→ 直接调 `generateAIReport`。

### 7.3 失败退款

报告生成抛异常时，若 `orderId` 对应订单 `amount>0`，catch 中自动 `cloud.callFunction({name:'requestRefund'})` 发起退款（用户无感知，不因 AI 失败扣钱）。

## 8. 会员 / 点数 / 套餐激活逻辑

均在 `payCallback` 内（支付成功后执行）。

### 8.1 会员 activateMember / activateFamilyMember
- 计算到期日：续费在 `max(当前到期, now)` 基础上加时长；新开从 now 起算。
- 时长：月卡 30 天、年卡 365 天（`MEMBER_DURATION`）。
- 重置周期：按开通日对齐（如 5 日开通 → 次月 5 日重置）。
- 同步 `users.isMember / memberExpire`。

### 8.2 点数 creditPoints
- `user_points.balance` `_.inc(count)`，顺延到期日（90 天，`POINTS_PACKS.expire_days`）。
- 写 `point_transactions` 流水。
- **依赖订单 metadata**：`points_count`、`expire_days`（createOrder 已对齐）。

### 8.3 套餐 processBundle
- 主订单 `bundle` 下挂多个子订单（`member_*` + `points`）。
- 把每个子订单置 `PAID`，再递归 `dispatchPostPayment` 分别激活会员与到账点数。

### 常量速查

```
PRICES: FIRST_REPORT=100, STANDARD_REPORT=990, MEMBER_MONTHLY=1990,
        MEMBER_YEARLY=9900, MEMBER_FAMILY_MONTHLY=2990, MEMBER_FAMILY_YEARLY=19900
POINTS_PACKS: PACK_3={count:3, price:1990, expire_days:90}, PACK_5={count:5, price:2990, ...}
MANUAL_REVIEW_THRESHOLD=9900   // ≥¥99 的订单标记 need_manual_review
ORDER_STATUS: pending/paid/refund_requested/refunded/failed/closed
```

> 价格/额度支持 DB 动态配置（`getPrices` / `loadPrices`），管理后台可改；上述是 [constants.js](../cloudfunctions/common/constants.js) 的默认值。

## 9. 退款流程

| 步骤 | 函数 | 说明 |
|------|------|------|
| 用户申请 | `requestRefund` | 建 `refund_records`（status=pending），订单置 `refund_requested` |
| 管理员审核 + 执行 | `processRefund` | 调集成函数 `/wx-pay/refund` 真正退款 |
| 退款回调 | 网关 → `payCallback` | 标记最终状态 |
| 自动退款 | `generateAIReport` catch | 报告生成失败时自动发起 |
| 回滚优惠 | `rollbackCoupon` / `refundPoint` | 退还已用券/点数 |

## 11. 部署

### 11.1 改过 `cloudfunctions/common/` 后必须同步
```bash
bash scripts/sync-common.sh          # 把 common/ 复制到各函数的 common/ 副本
bash scripts/sync-common.sh --check  # 仅校验
```
> 各云函数以 `require('./common/xxx')` 引用**本地副本**（微信云开发每个函数只打包自身目录）。

### 11.2 部署前检查
```bash
bash scripts/pre-deploy-check.sh     # 密钥、common 同步、var、require 路径
```
> 该脚本的「../common/」检查会把 common 副本里 JSDoc 注释示例也算进去（误报），真实调用为 0 即可。

### 11.3 用 tcb 部署
```bash
tcb login
tcb fn deploy createOrder --force
tcb fn deploy payCallback --force
tcb fn deploy generateAIReport --force
tcb fn deploy Mewora-1r02jkm1-demo-scfweb --force   # 改 env 必须带 --force
```
改集成函数 env（如回调地址）后，`--force` 才会把新 env 写入云端。

### 11.4 上线顺序

## 12. 常见问题排查

| 现象 | 排查 |
|------|------|
| 付了钱订单一直 `PENDING` | 看 `payCallback` 日志是否有回调到达；若没回调，检查 `notifyURLPayURL` 是否指向**网关**地址、`ResourceName` 是否=`payCallback` |
| 回调到达但验签/解密失败 | 确认 `signMode=gateway`、`apiV3Key` 正确；业务侧不应自己验签（已移除） |
| `payCallback` 字段读不到 | 看 `raw event` 日志，确认网关转发字段名；V2/V3 已兼容，异常字段贴出来加适配 |
| 下单报「支付通道暂不可用」 | 看 `createOrder` + 集成函数日志：多为 `privateKey`/`merchantSerialNumber`/`apiV3Key` 配错或私钥 `\n` 未转义 |
| 会员付了钱没开通 | 前端轮询超时？看 `payCallback` 是否成功 `activateMember`、`getMemberStatus` 返回 |
| 报告「请先购买」循环 | `resolveReportOrder` 没找到 PAID 单；确认 createOrder 的 `metadata.record_id` 与查询一致 |
| 订单重复扣额度 | 报告路径：确保只走 createOrder→payCallback；`resolveReportOrder` 的「先查单」防双扣 |

## 13. 安全要点

- **金额校验**：`payCallback` 校验微信回调金额 = 订单金额，不符拒处理并记对账。
- **幂等**：订单状态用 `where status=PENDING` 原子更新，重复回调安全。
- **签名/解密**：交给集成网关（`signMode=gateway`），业务侧收明文。
- **凭证不落源码**：私钥/密钥只放云函数 env；`secrets.js` 与 `tcb_query.json` 已 gitignore。
- **限流 + 风控**：createOrder 对下单做速率限制；付费订单调 `checkRiskControl`。
- **大额审核**：金额 ≥ `MANUAL_REVIEW_THRESHOLD`(¥99) 的订单标记 `need_manual_review`。
- **对账**：金额/状态不一致写 `BILL_CHECK_LOGS`，分发失败写 `ERROR_LOGS`，供补偿任务修复。
