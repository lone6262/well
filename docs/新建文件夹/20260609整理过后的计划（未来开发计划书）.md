# 宠脉AI — 未来开发计划书

## Context

基于 `docs/新建文件夹/` 中 7 份文档的深度分析（PRD、6 份多维度评审），结合当前 V1.5 代码库的实际实现状态（36 云函数、15+ 页面、12+ 数据库集合），梳理出以下开发路线图。

**核心问题：** V1.5 虽功能齐全，但缺乏 3 个关键支柱——用户标签体系、生命周期 CRM、宠物健康档案——这些是将「症状自查工具」升级为「AI 健康助手平台」的基础设施。

**战略定位转变：** 从「宠物症状自查小程序」→「宠脉AI — 宠物 AI 健康助手」

## Phase 2：V2.0 核心 — 三大缺失支柱

**工期：6-8 周（~30 工作日）**
**目标：构建数据驱动基础，从工具升级为平台**

### 2.1 用户标签体系（L5 — 核心资产）

**核心思路：** AI 自动分析用户行为打标签，为未来推荐、导流、精准营销提供基础。

```
user_tags 集合:
  breed, age_stage, weight_range, food_brand
  health_problem_tags: ['digestive', 'skin', 'respiratory'...]
  symptom_tags: ['vomiting', 'diarrhea'...]
  pay_level: 'free'|'low'|'medium'|'high'
  active_level: 'inactive'|'low'|'medium'|'high'
  multi_pet, auto_generated: ['digestive_sensitive', 'senior_pet'...]
```

**自动标签规则示例：**
- 连续 2+ 次消化系统自查 → `digestive_sensitive`
- 连续 2+ 次皮肤问题自查 → `skin_issues`
- 宠物年龄 > 老年阈值 → `senior_pet`
- 多只宠物 → `multi_pet`

**新增：** 3 个云函数（`generateUserTags` / `getUserTags` / `updateUserTag`），修改 `submitSymptom`、`savePet`、`login` 触发标签更新。工时：~4d

### 2.2 生命周期 CRM（L6）

**用户阶段流转：**

```
new → active → high_freq → vip → vip_annual
                                    ↓
              at_risk → lost → reactivated
```

| 阶段 | 触发条件 | 自动策略 |
|------|----------|----------|
| new → active | 完成首次自查 | 引导 1 元报告 |
| active → high_freq | 7 天内 3+ 次自查 | 推荐月卡 |
| active/high_freq → vip | 购买会员 | 推荐年卡 |
| 任意 → at_risk | 14 天未活跃 | 推送召回 |
| at_risk → lost | 30 天未活跃 | 发放回归券 |
| lost → reactivated | 回归并完成自查 | 新手礼包 |

**新增：** `user_lifecycle` 集合 + 4 个云函数（`updateLifecycle` / `getLifecycleDashboard` / `triggerReEngagement` / `sendExpireReminder`），修改 `submitSymptom`、`createOrder`、`memberActivate` 触发阶段更新。工时：~7d

### 2.3 宠物健康档案（L7 — 平台壁垒）

**核心功能：**
- 健康评分（0-100 分，AI 自动计算）
- 疫苗/驱虫记录与提醒
- 体重趋势曲线
- 月度健康评分趋势
- 健康摘要报告（PDF 可分享）

**健康评分算法：**
- 近期自查频率（20%）
- 症状风险等级（30%）
- 疫苗接种状态（15%）
- 驱虫状态（15%）
- 回访结果（10%）
- 年龄因子（10%）

**新增：** `pet_health_records` + `health_reminders` 集合，7 个新云函数，3 个新页面（`pages/health-record/index` / `add` / `reminders`）。工时：~12d

### Phase 2 产出汇总

- **新增集合：** `user_tags`, `user_lifecycle`, `pet_health_records`, `health_reminders`
- **新增云函数：** 14 个（标签 3 + CRM 4 + 健康档案 7）

## Phase 3：V2.0 增强 — 数据智能与内容

**工期：5 周（~25 工作日）**
**目标：数据驱动决策 + 降低 LLM 成本**

### 3.1 报告模板引擎（成本优化）

**核心策略：** 常见症状组合 → 预置模板（80% 静态内容）→ 仅个性化部分调用 LLM → Token 成本降低 80%

```
症状树: pet_type → symptom_combo → severity → Template
例: cat + vomit + appetite_normal → 模板 ID: cat_vomit_mild
```

- 修改 `report-engine.js`：先查模板 → 命中则仅调用 LLM 生成个性化建议
- 扩展 `report_templates` 集合：目标 50-100 个常见组合模板
- 模板增加 `version` 字段支持批量失效

工时：~5d

### 3.2 数据驾驶舱（漏斗分析 + 营收看板）

```
用户漏斗: 首页 → 开始自查 → 完成自查 → 报告页 → 支付 → 生成报告 → 复购 → 会员
```

- **新增集合：** `funnel_events`
- **新增云函数：** `trackFunnelEvent` / `getFunnelMetrics` / `getRevenueMetrics` / `getRetentionMetrics`
- **前端埋点：** 新建 `utils/tracker.js`，在关键页面注入事件追踪
- **管理后台扩展：** 漏斗图、营收趋势、留存分析、用户分群

工时：~7d

### 3.3 A/B 测试框架

- **新增集合：** `experiments` + `experiment_assignments`
- **新增云函数：** `getExperimentVariant` / `createExperiment` / `getExperimentResults` / `updateExperiment`
- **首批测试：** 报告价格（9.9 vs 6.9）、月卡价格（19.9 vs 29.9）、首页布局

工时：~4d

### 3.4 内容扩展 + 报告分享

- 知识库从 8 篇扩展到 50+ 篇（AI 批量生成初稿 + 人工审核）
- 增加 `member_only` 字段做会员专享内容
- 增加 SEO 元数据字段
- AI 报告增加分享功能（生成海报含二维码）

工时：~6d

### Phase 3 产出汇总

- **新增集合：** `funnel_events`, `experiments`, `experiment_assignments`
- **新增云函数：** 8 个
- **修改核心文件：** `report-engine.js`（模板引擎升级）

## 跨阶段注意事项

1. **战略重定位：** Phase 1 启动时立即修改 `app.json` 标题为「宠脉AI」，更新所有用户-facing 文案
2. **成本优先：** 若 DeepSeek API 成本成为瓶颈，Phase 3 的模板引擎可提前至 Phase 2 实施
3. **数据归档：** 每个阶段同步建立数据归档策略（rate_limits 7天、audit_logs 90天、orders 180天）
4. **安全加固：** 维持现有 rate-limiter + JWT + 输入验证 + 审计日志体系
5. **命名规范：** 云函数 camelCase、页面 kebab-case、集合 snake_case、常量 UPPER_SNAKE_CASE

## 验证方案

每个 Phase 完成后的验证步骤：
1. **Phase 1：** 模拟支付全流程（含中断恢复、优惠券抵扣、超时关闭），红线症状拦截测试，合规审核材料准备
2. **Phase 2：** 多用户场景标签自动生成测试，生命周期阶段流转测试，健康评分计算验证
3. **Phase 3：** 模板命中率监控（目标 >60%），漏斗数据准确性验证，A/B 测试分流一致性检查
4. **Phase 4：** 医院 CPS 全链路追踪测试，保险产品展示与跳转验证，体检报告 AI 解读准确性抽检
5. **Phase 5：** Agent 多轮对话连贯性测试，家庭医生订阅全流程，商城下单与物流追踪
