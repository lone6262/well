## 1. 产品定位

```
Mewora V1.5.5 不是：AI 数字宠物养成游戏
Mewora V1.5.5 是：  AI 宠物陪伴增强版
```

整体 UI 比例：**70% V1.5 健康专业体系 + 30% 情感陪伴元素**。

不是 30% 健康 + 70% 数字宠物。健康工具仍是产品的根，日记是根上长出的情感枝叶。

## 2. 要验证的唯一假设

> **"用内容工厂的 AI 生产能力驱动小程序的每日打开，能不能把工具型产品变成日活型产品？"**

三个可测量的子假设：

| 序号 | 子假设 | 验证方法 | pass 阈值 | fail 阈值 |
|------|--------|---------|----------|----------|
| H1 | AI 宠物日记能让用户次日回来 | 日记卡槽点击率 + 次日留存 | 留存 >= 25%，点击率 >= 15% | 留存 < 15% |
| H2 | 内容工厂每日推送能提升打开频次 | 日均打开次数 | >= 2.5 次（V1.5 基线 1.2） | < 1.8 次 |
| H3 | 订阅消息推送能有效召回 | 授权率 + 打开率 | 授权 >= 40%，打开 >= 15% | 授权 < 20% |

**验证纪律**：4 周结束后，如果 H1 红档（留存 < 15%），立即停止此方向，不再追加投入。

## 3. 功能边界（冻结）

### P0 必做

| 功能 | 目的 | 验证目标 |
|------|------|---------|
| 首页 AI 陪伴卡 | 提高首页停留 | H2 打开频次 |
| AI 宠物日记（自动生成 + 时间轴 + 历史） | 核心验证对象 | H1 留存 |
| 用户自选性格标签（创建宠物时选 1-2 个） | 影响日记语气 | 辅助 H1 |
| 日记分享（分享当前日记，非人格海报） | 品牌传播 + 回流 | 不设独立假设 |

### P1 可做

| 功能 | 说明 |
|------|------|
| 日记配图 | 宠物头像 + 文字组合图，不做 AI 写真 |

### P2 延后（全部移到 V1.5.6+）

- AI 写真（9.9 元）- 变现假设，与留存解耦
- 人格海报 / MBTI 分享 - 病毒传播假设，与留存目标方向相反
- 人格评分 / 百分比 / 人格成长 - 数据来源问题，冷启动无法成立
- 数字宠物详情页 / 数字宠物空间 - 隐性工期黑洞
- 四维状态系统（生机/灵犀/悠然/羁绊）- 复杂度高
- 情绪氧吧 / ASMR - 调性脱节
- 家族神兽 - 家庭社交假设
- 复杂皮肤商城 - 无验证价值
- 数字宠物 3D / Lottie 复杂动画 - 隐性工期

## 4. 获客漏斗

不是靠小程序内部裂变，而是靠内容工厂的公域流量导入：

```
公众号文章 / 小红书笔记（每日产出）
    |  文章底部嵌小程序码 / 小红书主页挂小程序卡片
    v
小程序首次打开 -> 创建宠物档案（首次数据采集 + 选性格标签）
    |
    v
首页今日科普（内容工厂当日推送）+ AI 陪伴卡（今日日记）
    |
    v
用户离开 -> 次日凌晨 AI 生成新日记
    |
    v
订阅消息"你的毛孩子今天有话要说" -> 用户回来
    |
    v
闭环：打开 -> 浏览 -> 行为数据 -> 次日日记 -> 推送 -> 回来
```

日记分享是这条漏斗的辅助入口：用户分享当天日记 -> 朋友看到 -> 扫码进入小程序。分享内容 = 留存内容，不引入新假设。

## 8. 云函数详细设计

### 8.1 syncDailyContent

**职责**：内容工厂推送当日文章到小程序首页

**输入**：
```json
{
  "title": "猫糖尿病的早期识别与居家管理",
  "summary": "...",
  "content": "...",
  "cover_url": "https://...",
  "category": "digestive",
  "target_pet": "cat",
  "token": "HMAC 签名 Token"
}
```

**逻辑**：
1. 鉴权：复用 `common/auth.js` 的 `verifyToken`
2. 查 `knowledge_articles` 是否已有同标题文章
3. 有则更新 `featured_date = today`，无则新增
4. 返回 `{ code: 0, article_id }`

### 8.2 generatePetDiary

**职责**：每日 00:30 定时触发，为每个活跃用户生成宠物日记

**核心逻辑**：

```javascript
exports.main = async (event, context) => {
  // 1. 获取所有有宠物的用户
  const pets = await db.collection('pets').get();
  
  for (const pet of pets.data) {
    try {
      await generateDiaryForUser(pet);
    } catch (e) {
      // 记录失败，不阻断其他用户
      logger.error('diary gen failed', pet.user_id, e.message);
    }
  }
};

async function generateDiaryForUser(pet) {
  const userId = pet.user_id;
  const today = formatDate(new Date());
  
  // 0. 检查今天是否已生成（幂等）
  const existing = await db.collection('pet_moments')
    .where({ user_id: userId, date: today }).count();
  if (existing.total > 0) return;
  
  // 1. 拉取昨日行为数据
  const yesterday = getYesterdayRange();
  const symptomChecks = await db.collection('symptom_records')
    .where({ user_id: userId, created_at: _.gte(yesterday.start).lt(yesterday.end) }).get();
  const knowledgeViews = await db.collection('analytics_events')
    .where({ user_id: userId, event_name: 'knowledge_view',
             created_at: _.gte(yesterday.start).lt(yesterday.end) }).count();
  
  // 2. 检查是否首次日记（冷启动）
  const diaryCount = await db.collection('pet_moments')
    .where({ user_id: userId }).count();
  const isFirst = diaryCount.total === 0;
  
  // 3. 选择模板
  let templateKey;
  if (isFirst) {
    templateKey = 'welcome';
  } else if (symptomChecks.data.length > 0) {
    templateKey = 'care';
  } else if (knowledgeViews.total > 0) {
    templateKey = 'learn';
  } else {
    templateKey = 'daily';
  }
  
  // 4. 模板填充
  const tags = pet.personality_tags || [];
  const template = selectTemplate(templateKey, pet.type, tags);
  const filled = fillTemplate(template, {
    pet_name: pet.name,
    pet_type: pet.type === 'cat' ? '猫咪' : '狗狗',
    symptoms: symptomChecks.data[0]?.symptom_names || '',
    days_since: daysSinceCreate(pet.created_at)
  });
  
  // 5. DeepSeek 润色（复用 report-engine）
  //    冷启动模板不调 AI，直接用填充结果（控成本）
  let content = filled;
  if (templateKey !== 'welcome' && needPolish(filled)) {
    try {
      content = await callDeepSeekForDiary(filled, pet);
      // max_tokens: 200, temperature: 0.8
    } catch (e) {
      // AI 失败，用模板填充结果兜底
      content = filled;
    }
  }
  
  // 6. 敏感词过滤（复用 sensitiveWords 逻辑）
  content = filterSensitive(content);
  
  // 7. 写入 pet_moments
  await db.collection('pet_moments').add({
    data: {
      user_id: userId,
      pet_id: pet._id,
      date: today,
      content: content,
      type: 'diary',
      source: 'auto',
      mood: pickMood(templateKey),
      template_used: templateKey,
      is_first: isFirst,
      created_at: new Date()
    }
  });
}
```

### 8.3 getPetDiary

**职责**：查询用户日记列表

**逻辑**：

## 11. 视觉设计约束

### 继承 V1.5

- 基础背景：白色 / `--bg-color`（#FDFAF7）
- 健康状态色：`--color-success` / `--color-warning`
- 卡片布局：`--bg-card` + `--shadow-sm` + `--radius-lg`
- 字体系统：全部走 design-tokens 的 CSS 变量
- **禁止**：硬编码色值、emoji、渐变（V1.5 Phase 1-6 已全量清理）

### 新增情感元素

- 宠物头像：用真实头像（用户上传）或 paw.svg 占位，不做动态头像
- 暖色调卡片：陪伴卡用 `--brand-primary-light` 背景，区别于科普卡片的 `--color-info-light`
- 轻动画：仅 CSS `@keyframes`（呼吸动画 opacity 微变、卡片点击反馈），不做 Lottie
- 心情表达：用文字 + paw 图标，不用 emoji

## 13. 成本估算

| 成本项 | 估算 | 控制策略 |
|--------|------|---------|
| DeepSeek 日记生成 | 每用户每天 1 次，单次 <= 200 token | 模板填充 70% + AI 润色 30%；冷启动纯模板不调 AI |
| 订阅消息推送 | 按授权用户数 | 仅推送给授权用户；未授权走 Banner |
| 云数据库存储 | pet_moments 每用户每天 1 条 | 免费用户 7 天 TTL 自动清理 |
| 内容工厂推送 | 每天 1 次 HTTP 调用 | 忽略不计 |

**月成本增量预估**：DAU 500 的情况下，AI Token + 数据库 + 消息推送合计 < 50 元/月。

## 14. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 订阅消息授权率极低（< 20%） | 高 | 召回闭环断裂 | Banner 兜底 + 多触点引导授权 |

## 16. 关键决策记录

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 验证几个假设 | 1 个（日记驱动留存） | 样本量有限，多假设并行稀释信号 |
| 数字宠物形象 | 不做（纯文字日记） | UI 资产从零起步是最大隐性工期 |
| TabBar | 不动 | 五个 tab 都有明确价值，日记放首页足够 |
| 获客渠道 | 自媒体公域导流 | 内容工厂已有产出，不额外花钱投流 |
| 日记 AI 比例 | 模板 70% + AI 30% | 控成本，冷启动纯模板不调 AI |
| 人格系统 | 用户自选 1-2 个标签 | 零数据冷启动也能成立，不做百分比计算 |
| 排除 AI 写真 | V1.5.6 | 变现假设与留存假设解耦 |
| 排除人格海报 | V1.5.6 | "用完即走"病毒机制与留存目标反向 |
| 保留日记分享 | 做 | 分享内容 = 留存内容，不引入新假设 |
| 动画策略 | 仅 CSS keyframes | 不做 Lottie / 3D，控制工期 |
| UI 比例 | 70% 健康 + 30% 情感 | 健康是根，日记是枝叶 |
