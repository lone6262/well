## 1. 项目简介

### 1.1 产品定位

**宠脉AI**是一款基于微信小程序的宠物健康自查工具，面向猫狗主人，提供AI驱动的症状评估、健康报告生成、医院搜索、会员服务等一站式宠物健康管理能力。

### 1.2 技术栈

| 层次 | 技术选型 |
|------|---------|
| 前端 | 微信小程序原生框架 (WXML + WXSS + JS) |
| 管理后台 | HTML5/CSS3/JS (Vanilla JS) + Vite 打包 |
| 后端 | 微信云开发 (CloudBase) — 云函数 + 云数据库 |
| AI 引擎 | DeepSeek Chat API (deepseek-chat) |
| 地图服务 | 腾讯地图 API |
| 支付系统 | 微信支付 (cloud.cloudPay.unifiedOrder) |
| 认证 | HMAC-SHA256 JWT Token |
| 测试 | Vitest (单元测试) + 手动集成测试 |

|------|-----|

### 1.4 V1.5 版本亮点

V1.5 在 V1.1 基础上实现了**商业化增强**，核心新增：

- 💰 **支付系统**: 支持报告/会员/点数包/套餐 4 类订单 + 优惠券 + 退款
- 👑 **会员体系**: 个人/家庭月卡/年卡 + 体验会员 + 自动续费
- 📊 **管理后台**: 10+ 模块 Web 管理端（用户/订单/退款/优惠券/风控/对账）
- 🤖 **AI 报告商业化**: 首份 ¥1.00 → 标准 ¥9.90，多级额度智能解析
- 🎫 **邀请裂变**: 邀请奖励 + 排行榜 + 阶梯里程碑
- 🔒 **安全加固**: 速率限制、风控检查、审计日志、支付签名验证

### 3.2 架构原则

1. **Serverless 优先**: 全部后端逻辑跑在微信云函数上，零服务器运维
2. **缓存先行**: AI 报告采用 缓存 → DeepSeek → 模板 三级回退
3. **弹性降级**: 网络/服务/云不可用时自动进入游客/离线模式
4. **原子操作**: 订单创建使用条件更新 + 回滚确保数据一致性
5. **幂等设计**: 支付回调、额度扣减等关键操作支持幂等重试
6. **安全分层**: Token 认证 → 交叉验证 → 速率限制 → 风控检查

支持的订单类型:

| 类型 | 子类型 | 价格 | 示例 |
|------|--------|------|------|

| `member_monthly` | 个人月卡 | ¥19.90 | 月费 |

| `bundle` | STARTER / ESSENTIAL / FAMILY | ¥29.90 / ¥119 / ¥39.90 | 套餐 |

**额度智能解析** — resolveQuota 优先级:
1. 首份优惠 (`first_report`) → ¥1.00
2. 邀请奖励 (`invite`) → 免费
3. 体验会员 (`trial`) → 免费（每月1次）
4. 正式会员 (`member`) → 免费（每月3-6次）
5. 点数包 (`points`) → 消耗1个点数
6. 付费 (`paid`) → ¥9.90

**防并发与数据一致性问题**:
- ✅ 条件更新 (`_.neq(true)`, `_.lt(total)`): 防止并发重复扣减
- ✅ 余额扣减失败自动回滚 (rollbackQuota)
- ✅ 重复订单二次去重检测
- ✅ 优惠券锁定状态 (unused → locked → used)

  // 3. 幂等性检查（防重复回调）
  // 4. 更新订单状态
  // 5. 发放权益
  // 6. 处理邀请奖励
}

## 12. 安全体系

### 12.1 认证安全

```
┌─────────────────────────────────────────┐
│  认证安全策略                              │
│                                          │
│  1. JWT Token (HMAC-SHA256)              │
│     - 签名防止篡改                          │
│     - 1天过期 + 前端自动续期                │
│     - 时序安全比较 (crypto.timingSafeEqual)│
│                                          │
│  2. 交叉验证                               │
│     - Token.openid === WXContext.OPENID  │
│     - 防止 Token 跨用户盗用                 │
│                                          │
│  3. 密钥管理                               │
│     - 密钥存在 database system_config     │
│     - warmupConfig(db) 懒加载             │
│     - 永远不硬编码在前端代码中               │
└─────────────────────────────────────────┘
```

### 12.2 安全防护层

| 层次 | 措施 | 实现 |
|------|------|------|
| **输入验证** | 症状 ID 白名单 | `VALID_SYMPTOM_SET` (24个) |
| **速率限制** | 每用户每操作限频 | `rate-limiter.js` (10次/分钟) |
| **风控检查** | ≥¥99 订单需审核 | `checkRiskControl` + 手动审核标记 |
| **数据脱敏** | 日志脱敏 | `logger.js` sanitize |
| **审计追踪** | 敏感操作记录 | `audit-logger.js` |
| **XSS 防护** | HTML 转义 | 管理后台 `escapeHtml()` |
| **支付安全** | 签名验证 + 幂等 | `payCallback` + 金额校验 |
| **权限控制** | Token 交叉验证 | `auth.js::authenticate()` |

### B. 关键决策记录

| 决策 | 理由 |
|------|------|
| 云函数选用 Node.js 而非 Go/Python | 微信原生支持，减少环境差异 |
| Vanilla JS 管理后台而非 React/Vue | 降低构建复杂度，CloudBase 静态托管更简单 |
| 模拟支付模式 | 加快开发速度，商户号审核周期长 |
| 条件更新实现原子操作 | 微信云数据库不支持事务，此方案最可靠 |
| 三层报告生成 (缓存→AI→模板) | 降低成本 + 提高成功率 |
