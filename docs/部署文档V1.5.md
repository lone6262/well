## 3. 微信小程序注册与配置

### 3.1 注册小程序

1. 访问 [微信公众平台](https://mp.weixin.qq.com) → 立即注册 → 小程序
2. 选择主体类型（个人/企业/政府/其他组织）
   - **个人主体**：无法使用微信支付和部分类目
   - **企业主体**：完整功能，需营业执照
3. 填写邮箱、密码，激活账号
4. 完成主体信息登记和认证（企业需支付 ¥300/年认证费）

### 3.2 完善小程序信息

登录小程序后台 → **设置**:

```
基本设置:
├── 小程序名称: 宠脉AI（或自定义）
├── 小程序简称: 宠脉AI
├── 头像/Logo: 上传 144×144 图标
├── 介绍: 宠物健康自查与AI报告工具
└── 服务类目:
    ├── 工具 → 信息查询
    └── 医疗健康 → 健康管理（如需要，需提供资质）

成员管理:
├── 添加开发者（微信号）
```

## 5. 数据库初始化

### 5.1 调用 dbInit 云函数（方式一：微信开发者工具）

在部署所有云函数之前，先单独部署 `dbInit` 云函数：

1. 在微信开发者工具中，右键 `cloudfunctions/dbInit` → **上传并部署：云端安装依赖**
2. 等待部署完成（约 30-60 秒，需下载 Node.js 依赖）
3. 在微信开发者工具打开 **云开发控制台** → 云函数 → dbInit → **调用测试**
4. 传入参数:

```json
{
  "adminSecret": "your-admin-secret-at-least-32-chars",
  "tokenSecret": "your-token-secret-at-least-32-chars",
  "tencentMapKey": "your-tencent-map-key",
  "deepseekApiKey": "sk-your-deepseek-api-key",
  "deepseekBaseUrl": "https://api.deepseek.com",
  "deepseekModel": "deepseek-chat",
  "mode": "init"
}
```

5. 等待执行完成，看到 `🎉 数据库初始化完成！` 即表示成功

### 5.2 调用 dbInit（方式二：云开发控制台 SQL）

也可在云开发控制台 → 数据库 → 直接点击 **新建集合**，手动创建所有集合:

```
需要创建的 22 个集合:
system_config | users | pets | symptom_records | orders
ai_cache | hospitals | members | knowledge_articles
invite_records | followup_records | report_templates
rate_limits | audit_logs | refund_records | user_points
point_transactions | user_coupons | coupons | member_renew_log
bill_check_logs | analytics_events | error_logs
```

然后通过 dbInit 仅写入种子数据（医院、知识文章、报告模板）。

### 5.3 手动创建数据库索引

在**云开发控制台 → 数据库 → 对应集合 → 索引管理**中创建以下索引:

```sql
-- system_config
CREATE UNIQUE INDEX key_unique ON system_config(key)

-- users
CREATE UNIQUE INDEX openid_unique ON users(openid)

-- pets
CREATE INDEX user_id ON pets(user_id)
CREATE UNIQUE INDEX user_id_petCode_unique ON pets(user_id, petCode)

-- symptom_records
CREATE INDEX user_id ON symptom_records(user_id)
CREATE INDEX pet_id ON symptom_records(pet_id)
CREATE INDEX user_id_created_at ON symptom_records(user_id, created_at DESC)

-- orders ⚠️ 高频查询，索引必须全
CREATE UNIQUE INDEX out_trade_no_unique ON orders(out_trade_no)
CREATE UNIQUE INDEX transaction_id_unique ON orders(transaction_id)
CREATE INDEX user_id_created_at ON orders(user_id, created_at DESC)
CREATE INDEX status ON orders(status)

-- members
CREATE UNIQUE INDEX user_id_unique ON members(user_id)
CREATE INDEX expire_date ON members(expire_date)
CREATE INDEX status ON members(status)

-- ai_cache
CREATE UNIQUE INDEX symptoms_hash_unique ON ai_cache(symptoms_hash)
CREATE INDEX expire_at ON ai_cache(expire_at)

-- invite_records
CREATE INDEX inviter_id_created_at ON invite_records(inviter_id, created_at DESC)
CREATE INDEX invitee_id ON invite_records(invitee_id)
CREATE INDEX invitee_ip_created_at ON invite_records(invitee_ip, created_at DESC)

-- followup_records
CREATE INDEX record_id ON followup_records(record_id)
CREATE INDEX user_id_status ON followup_records(user_id, status)
CREATE INDEX status_created_at ON followup_records(status, created_at DESC)

-- knowledge_articles
CREATE INDEX category_sort_order ON knowledge_articles(category, sort_order)
CREATE INDEX status ON knowledge_articles(status)

-- rate_limits
CREATE INDEX openid_action_created_at ON rate_limits(openid, action, created_at DESC)
```

### 5.4 验证初始化结果

初始化完成后，在云开发控制台 → 数据库 中确认:

- [ ] `knowledge_articles` 集合至少有 5+ 篇文章
- [ ] `report_templates` 集合至少有 3+ 条模板
- [ ] `system_config` 集合有 6 条密钥记录
- [ ] `pets` 集合有示例宠物数据

## 6. 云函数部署

### 6.1 部署顺序

云函数之间有依赖关系，按以下顺序部署:

```
第一批（公共模块依赖，无前置）:
  login | silentLogin | quickLogin | saveUserProfile
  savePet | getPetList | deletePet
  getHospitals | searchHospitals
  getKnowledgeList | getKnowledgeDetail
  quickstartFunctions

第二批（依赖 users/pets/symptom_records 集合）:
  submitSymptom
  getRecordList | getRecordDetail | deleteRecord
  getFollowupList | getFollowupDetail | followupSubmit

第三批（依赖 system_config + common 模块）:
  generateAIReport          ← 依赖 DeepSeek API Key
  createOrder | orderList | orderDetail | cancelOrder
  payCallback | closeExpiredOrders
  requestRefund | processRefund

第四批（会员系统，依赖 users/members/orders 集合）:
  memberActivate | getMemberStatus
  cancelMembership | toggleAutoRenew
  checkExpiredMembers | checkAndFixMemberType
  renewMemberByAuto | sendExpireReminder

第五批（营销系统）:
  applyCoupon | receiveCoupon | getUserCoupons
  autoIssueCoupon | rollbackCoupon | expireCoupons
  createInvite | processInviteReward
  getInviteRanking | getInviteStats

第六批（积分 + 家庭）:
  consumePoint | refundPoint | purchasePoints
  getPointsBalance | getPointTransactions
  acceptFamilyInvite | inviteFamilyMember
  removeFamilyMember | getFamilyMembers

第七批（运维 + 管理）:
  checkRiskControl | checkDailyBill
  checkReportQuota | getUserStats | trackEvent
  adminLogin | adminGateway
  adminGetUsers | adminGetOrders | adminUpdateOrder
  adminGetArticles | adminSaveArticle | adminDeleteArticle
  adminGetStats | adminGetConfig | adminUpdateConfig
  generateSharePoster | cleanExpiredCache
  sendPaymentNotification
```

### 6.2 部署方式

在**微信开发者工具**中:

### 6.3 部署验证

每个云函数部署完成后，在**微信开发者工具 → 云开发控制台 → 云函数**中:

- [ ] 确认所有 65 个云函数状态为「部署成功」
- [ ] 点击 `silentLogin` → 测试调用，确认返回 `code: 0`
- [ ] 点击 `getHospitals` → 测试调用，确认返回医院数据
- [ ] 点击 `generateAIReport` → 测试调用，确认报告生成成功

### 6.4 常见云函数部署问题

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `npm install 失败` | 网络问题 / 依赖版本冲突 | 检查网络；删除 `node_modules` 重新部署 |
| `DATABASE_COLLECTION_NOT_EXIST` | 集合未创建 | 先执行 dbInit 初始化数据库 |
| `FunctionName duplicated` | 函数已存在 | 覆盖上传即可，不影响 |
| `依赖包过大` | node_modules 超 10MB | 确认 `.gitignore` 排除 node_modules |
| `warmupConfig 查询超时` | system_config 无数据 | 检查 dbInit 是否成功写入密钥 |

编辑 [admin/js/config.js](admin/js/config.js)，确认环境 ID:

```javascript
const TCB_CONFIG = {
  env: 'cloud1-d8gdi44zqfec250b5'  // ← 确认是你的环境 ID
};
```

### 7.4 首次登录管理后台

1. 访问静态托管域名
2. 使用在 `dbInit` 中设置的 `adminSecret` 作为密码
3. 用户名任意（当前版本仅校验密码）
4. 登录成功后，Token 有效期 24 小时

### 7.5 安全建议

```
生产环境:
├── 设置静态托管访问 IP 白名单（如果固定办公 IP）
├── 启用 HTTPS（CloudBase 默认支持）
├── 定期更换 ADMIN_SECRET（在 system_config 集合中更新）
├── 不要将 adminSecret 暴露在客户端代码中
└── 建议配置自定义域名 + CDN
```

> ⚠️ **安全警告**: 当前管理后台的 `adminLogin` 仅校验 `adminSecret`。建议增加用户名密码双重验证或 IP 白名单。

## 8. 微信支付配置

### 8.1 开通微信支付

1. 登录**微信支付商户平台** (https://pay.weixin.qq.com)
2. 完成商户入驻（需营业执照、法人身份证、银行账户）
3. 在**小程序后台** → 功能 → 微信支付 → 关联商户号
4. 获取以下信息:

| 信息 | 获取位置 |
|------|---------|
| 商户号 (mchid) | 账户中心 → 商户信息 |
| APIv3 密钥 | API 安全 → 设置 APIv3 密钥 |
| API 证书序列号 | API 安全 → 申请 API 证书 |
| API 证书私钥 | 下载的 `apiclient_key.pem` |

将支付密钥配置到 `system_config` 集合中（通过管理后台或直接操作数据库）:

## 10. 常见问题排查

### 10.1 云函数调用失败

**现象**: 小程序提示"网络异常"或"操作失败"

**排查步骤**:
1. 检查云函数是否部署成功（控制台 → 云函数 → 状态）
2. 检查云函数日志（控制台 → 云函数 → 日志）
3. 检查 `warmupConfig` 是否超时（查看 system_config 集合是否有数据）
4. 检查速率限制是否触发（查看 rate_limits 集合记录）
5. 检查网络请求是否在合法域名白名单中

### 10.2 DeepSeek API 不可用

**现象**: AI 报告始终返回模板内容（source: template）

**排查步骤**:
1. 检查 DeepSeek 平台 API Key 是否有效
2. 检查账户余额是否充足
3. 检查 `system_config` 中 `deepseek_api_key` 正确无误
4. 检查云函数日志中的 DeepSeek 错误信息
5. 确认 `deepseek_base_url` 为 `https://api.deepseek.com`

### 10.3 数据库操作失败

**现象**: `DATABASE_COLLECTION_NOT_EXIST` 或权限错误

**排查步骤**:
1. 确认集合已创建（控制台 → 数据库 → 集合列表）
2. 确认索引已创建（控制台 → 数据库 → 索引管理）
3. 检查集合权限设置（控制台 → 数据库 → 权限设置）
4. 对于服务端操作，确认使用 `cloud.getWXContext().OPENID`

### 10.4 管理后台无法登录

**现象**: 登录后提示"身份验证失败"

**排查步骤**:
1. 确认 `system_config` 中 `admin_secret` 值正确
2. 确认 `warmupConfig` 在 adminLogin 中正常执行
3. 检查云函数日志是否有认证失败记录
4. 尝试在云开发控制台直接调用 adminLogin 测试

### 10.5 支付相关问题

**MOCK_PAY 模式提示**:
```javascript
// createOrder/index.js 第 29 行
const MOCK_PAY = true; // ← 上线前必须改为 false
```

**模拟支付特征**:
- 订单状态直接为 `paid`（无需真实支付）
- `transaction_id` 以 `MOCK_` 开头
- `metadata.mock_pay` 为 `true`

### 10.6 图片/文件上传失败

**排查步骤**:
1. 确认云存储已开通
2. 检查云存储权限（公开读需开启）
3. 检查图片大小（前端限制 10MB）
4. 检查网络状态
