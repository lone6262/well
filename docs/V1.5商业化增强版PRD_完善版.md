## 三、AI报告付费系统

### 3.1 定价策略

| 类型 | 价格 | 条件 |
|---|---|---|
| 新用户首份报告 | ¥1.00 | 每个用户仅限1次，`users.first_report_used` 标记 |
| 标准AI报告 | ¥9.90 | 非会员按次付费 |
| 会员免费报告 | ¥0.00 | 每月3次额度，超出后可按次购买 |
| 邀请奖励报告 | ¥0.00 | 邀请/被邀请各获得1次 |

### 3.2 AI报告生成流程

```
用户完成自查 → 展示风险评估预览（免费，规则引擎结果）
    ↓
用户选择"获取AI详细报告" → 检查报告额度
    ↓
┌─ 有免费额度 → 扣减额度 → 生成报告
├─ 无免费额度 → 进入支付流程 → 支付成功 → 生成报告
└─ 会员且有余量 → 扣减会员额度 → 生成报告
    ↓
AI报告生成（generateAIReport 云函数）
    ↓
┌─ 查 ai_cache（symptoms_hash 匹配）→ 命中：直接返回缓存报告
└─ 未命中 → 调用 LLM API → 缓存结果 → 返回报告
    ↓
展示完整AI报告（8个章节）
```

### 3.3 AI报告内容结构（8个章节）

| 章节 | 内容说明 | 数据来源 |
|---|---|---|
| 1. 风险等级 | 综合风险评级（低/中/高）+ 可视化 | 规则引擎 |
| 2. 症状分析 | 每个选中症状的详细解读 | LLM/模板 |
| 3. 家庭护理建议 | 可在家执行的护理措施 | LLM/模板 |
| 4. 观察指标 | 需要持续观察的关键指标 | LLM/模板 |
| 5. 风险升级信号 | 出现哪些情况需立即就医 | LLM/模板 |
| 6. 就医建议 | 是否需要就医 + 就医时告诉医生什么 | 规则引擎 + LLM |
| 7. 常见误区 | 1-2个与当前症状相关的常见错误认知 | LLM/模板 |
| 8. 免责声明 | 法律免责 + 建议线下就医 | 固定文案 |

### 3.4 AI报告技术方案

#### 混合方案（模板 + LLM）

**Tier 1: 增强规则引擎模板（基础方案，零边际成本）**
- 基于现有规则引擎输出 risk_level
- 按症状组合 + 宠物类型 + 年龄段选择预置模板
- 每个组合准备 2-3 个变体，避免千篇一律
- 模板存储在云数据库 `report_templates` 集合中

**Tier 2: LLM API 增强（推荐）**

| LLM 服务 | 单次成本 | 延迟 | 推荐度 | 说明 |
|---|---|---|---|---|
| DeepSeek API | ~0.005元 | 2-5s | ⭐⭐⭐ | 性价比最高，推荐首选 |
| 阿里通义千问 | ~0.01元 | 2-4s | ⭐⭐ | 稳定性好，备选 |
| 百度文心一言 | ~0.01元 | 3-6s | ⭐⭐ | 可选 |

**LLM Prompt 设计（结构化输出）：**

```
你是一位专业的宠物健康顾问AI。根据以下信息生成宠物健康评估报告。

宠物信息：
- 类型：{pet_type}
- 品种：{breed}
- 年龄：{age}
- 体重：{weight}kg

症状信息：
- 症状列表：{symptom_names}
- 描述：{description}
- 持续时间：{duration}
- 严重程度：{severity}

规则引擎初步评估：{risk_level}风险

请严格按以下JSON格式输出报告：
{
  "risk_level": "low|medium|high",
  "risk_summary": "一句话风险概述",
  "symptom_analysis": [{"name": "症状名", "explanation": "详细解释"}],
  "home_care": ["建议1", "建议2", "建议3"],
  "observation_indicators": ["观察指标1", "观察指标2"],
  "escalation_signals": ["升级信号1", "升级信号2"],
  "vet_recommendation": {"needed": true/false, "urgency": "low|medium|high", "what_to_tell_vet": "..."},
  "common_misconceptions": [{"myth": "错误认知", "fact": "正确做法"}],
  "disclaimer": "免责声明固定文案"
}
```

#### 容灾机制

| 场景 | 处理方式 |
|---|---|
| LLM 调用超时（>15s） | 降级为模板报告，标记为"基础版" |
| LLM 返回格式错误 | JSON 解析失败则用模板填充 |
| LLM 服务不可用 | 直接返回模板报告 |
| 缓存命中 | 直接返回缓存内容，不调用 LLM |

### 4.3 会员生命周期

```
购买 → 激活(memberActivate) → 使用中 → 到期前3天提醒
  ↓                              ↓
取消(auto_renew=false)        正常到期
  ↓                              ↓
到期后仍可用至到期日          状态变为 expired
                                ↓
                            续费提醒 → 再次购买
```

### 4.4 额度管理

**月度报告额度重置规则：**
- `report_credits_reset_at`：下次重置时间
- 每次查询会员状态时，若 `now >= report_credits_reset_at`，则使用原子操作重置：
  ```javascript
  // ⚠️ 使用原子操作避免并发竞态条件
  await db.collection('members').doc(memberId).update({
    data: {
      report_credits_used: 0,
      report_credits_reset_at: db.command.push( // 设为下个月对齐日
        new Date(old_reset_at.getTime() + 30 * 24 * 3600 * 1000)
      )
    }
  })
  ```
- 扣减额度使用原子操作 + 前置条件检查：
  ```javascript
  // 先检查额度再扣减（单次原子操作）
  const result = await db.collection('members').where({
    _id: memberId,
    report_credits_used: _.lt(_.getField('report_credits_total')) // 前置条件
  }).update({
    data: {
      report_credits_used: db.command.inc(1)
    }
  })
  if (result.stats === 0) {
    // 额度不足，引导按次付费
  }
  ```

### 4.5 边界情况处理

| 场景 | 处理方式 |
|---|---|
| 会员额度用完后购买报告 | 允许按次付费 ¥9.90 |
| 会员取消 | 设置 `auto_renew = false`，保留至到期日 |
| 会员到期前续费 | 新到期日 = 旧到期日 + 时长（不从今天算起） |
| 并发消耗同一额度 | 原子操作 `db.command.inc` + 额度检查前置条件 |
| 年卡降级月卡 | V1.5 不支持，需取消后重新购买 |
| 到期后 `users.isMember` 更新 | 每次 `getMemberStatus` 调用时同步冗余字段 |

```

    ↓

    ↓

    ↓

    ↓
更新 invite_records + 双方奖励状态
```

### 5.3 反作弊措施

> ⚠️ PRD 原稿未涉及反作弊，这是必须补充的内容。

| 措施 | 实现方式 | 说明 |
|---|---|---|
| 设备指纹限制 | `wx.getSystemInfoSync()` 收集设备信息 | 每设备每日最多领取3次被邀请奖励 |
| IP 限流 | 云函数 `event.requestContext` 获取客户端 IP | 同一 IP 每日最多5次邀请奖励 |
| 最低使用门槛 | 被邀请人须完成至少1次自查 | 防止注册即领奖 |
| 频率限制 | 每用户每日最多50次邀请 | 防止脚本刷量 |
| 新用户校验 | 被邀请人 `loginCount === 1` | 防止老用户冒充新用户 |
| 奖励上限 | 每用户每月最多获得10次邀请奖励 | 防止无限刷报告 |

## 六、24小时回访闭环

### 6.1 微信小程序推送限制

> ⚠️ 微信小程序**不支持**任意推送通知，这是关键限制。

| 机制 | 要求 | V1.5可行性 |
|---|---|---|
| 一次性订阅消息 | 用户每次点击"允许"才可发1条 | ✅ 可用 |
| 长期订阅 | 仅政务/医疗/金融类小程序 | ❌ 不可用 |
| 公众号消息 | 需关注关联公众号 | V2.0考虑 |

### 6.2 回访实现方案

**双重触发机制：**

1. **订阅消息（需授权）**
   - 自查完成时弹出授权弹窗（`wx.requestSubscribeMessage`）
   - 用户授权后，24小时后发送订阅消息提醒
   - 订阅消息模板需提前在管理后台配置并审核

2. **首页弹窗（无需授权，最可靠）**
   - 每次启动时查询 `followup_records` 中 status = 'pending' 且 created_at ≤ now 的记录
   - 首页顶部显示回访提醒横幅："你的宠物昨天有症状，现在怎么样了？"
   - 点击进入回访提交页

### 6.3 订阅消息模板

需在微信小程序管理后台配置：

```
模板标题：宠物症状跟进提醒
{{pet_name}}的症状跟进提醒
症状：{{symptom_list}}
检查时间：{{check_time}}
请点击查看恢复情况
```

### 6.4 回访数据价值

- 记录好转/无变化/恶化比例
- 积累真实健康数据
- 后续可用于校准规则引擎风险阈值
- 例：若80%的"低风险"恶化案例都包含症状X，则X应提升至中风险权重

### 9.2 核心云函数详细设计

#### createOrder（创建订单）

```javascript
// 入参
{
  type: 'report' | 'member_monthly' | 'member_yearly',
  record_id: String,        // report类型必填
  pet_id: String,           // report类型必填
  is_first_report: Boolean  // 是否使用新用户首份优惠
}

// 出参
{
  code: 0,
  data: {
    out_trade_no: String,
    payment_params: Object   // wx.requestPayment 所需参数
  }
}

// 核心逻辑
1. 通过 cloud.getWXContext().OPENID 获取用户 openid（不从客户端接收）
2. 验证 token（从 event 中获取）
3. 检查报告额度（checkReportQuota 逻辑）
4. 计算金额（首份1元/标准9.9元/会员月卡19.9/年卡99）
5. 创建 orders 记录（status: 'pending', amount 单位为分）
6. 调用 cloud.cloudPay.unifiedOrder() 获取支付参数
7. 设置 time_expire（30分钟）
8. 返回支付参数
```

#### payCallback（支付回调）

```javascript
// 入参：微信支付服务器回调数据
// 无需手动调用，微信支付自动触发

// 核心逻辑
1. 验证支付签名（防伪造）
2. 根据 out_trade_no 查找 orders 记录
3. 校验金额一致性
4. 更新 order 状态为 'paid'
5. 根据 order.type 触发后续动作：
   - 'report': 触发 generateAIReport
   - 'member_monthly' / 'member_yearly': 触发 memberActivate
6. 返回成功响应给微信支付服务器
```

#### generateAIReport（生成AI报告）

```javascript
// 入参
{
  record_id: String,
  order_id: String          // 关联订单
}

// 出参
{
  code: 0,
  data: {
    report_id: String,
    content: Object,        // 8章节报告内容
    source: 'cache' | 'template' | 'llm'
  }
}

// 核心逻辑
1. 获取 openid（服务端）
2. 查询 symptom_record + pet 信息
3. 生成 cache_key = MD5(sorted(symptom_ids) + pet_type + age_range)
4. 查 ai_cache → 命中则直接返回
5. 未命中：
   a. 构造 LLM prompt（宠物信息 + 症状 + 规则引擎结果）
   b. 调用 LLM API（设置15秒超时）
   c. 解析 JSON 响应
   d. 失败则降级为模板报告
6. 写入 ai_cache（expire_at = now + 24h）
7. 更新 symptom_record.has_ai_report = true
8. 创建 followup_record（created_at = now + 24h）
9. 返回报告内容
```

#### getMemberStatus（查询会员状态）

```javascript
// 入参：无（自动从 cloud.getWXContext 获取 openid）

// 出参
{
  code: 0,
  data: {
    is_member: Boolean,
    type: 'monthly' | 'yearly' | null,
    expire_date: Date,
    days_remaining: Number,
    report_credits_total: Number,
    report_credits_used: Number,
    report_credits_remaining: Number,
    next_reset_at: Date
  }
}

// 核心逻辑
1. 查询 members 集合（user_id + status='active'）
2. 检查 expire_date：
   - 已过期 → 更新 status='expired', 同步 users.isMember=false
   - 未过期 → 检查额度是否需要重置
3. 如果 now >= report_credits_reset_at → 重置 used=0, 更新 reset_at
4. 同步 users 集合的 isMember 和 memberExpire 冗余字段
5. 返回完整会员状态
```

## 十、安全设计

### 10.1 V1.0 遗留安全修复（V1.5 前必须完成）

| 问题 | 修复方式 | 影响范围 |
|---|---|---|
| openid 客户端传递 | 所有云函数改用 `cloud.getWXContext().OPENID` | 7个云函数 |
| Token 未验证 | 支付/会员云函数强制验证 token | 新增云函数 |
| console.log 泄露 openid | 移除所有敏感信息日志 | 全局 |
| searchHospitals SDK 版本 | 从 `"latest"` 固定为具体版本 | 1个云函数 |

### 10.2 支付安全

- 金额存储单位统一为**分**（fen），避免浮点精度问题
- `payCallback` 必须验证微信支付签名
- 不信任前端回调参数，以微信支付回调数据为准
- `out_trade_no` 唯一约束防重复支付
- 订单30分钟超时自动关闭

### 10.3 API 安全

- 所有写入操作的云函数需验证用户身份
- 敏感操作（支付、退款、会员）需额外验证 token
- 限制单个用户的请求频率（防止暴力攻击）

## 十七、关键页面流程

### 核心变现流程

```
首页 → 症状自查 → 选症状 → 描述 → 提交
    ↓
风险预览（免费，规则引擎结果）
    ↓
"获取AI详细报告" 按钮
    ↓
┌─ 有免费额度（首次/邀请奖励）→ 直接生成
├─ 会员有余量 → 扣减额度 → 直接生成
└─ 无额度 → 支付确认页 → 微信支付 → 支付成功
    ↓
AI报告生成中（loading）
    ↓
AI完整报告（8章节）
    ↓
分享 → 24小时回访 → 留存运营
```

### 会员购买流程

```
会员中心页 → 选择月卡/年卡 → 确认购买 → 微信支付 → 激活会员
    ↓
会员状态页（权益展示、额度查看、到期提醒）
```

### 裂变流程

```
用户点击"邀请好友" → 选择分享方式
    ↓
┌─ 分享卡片 → 发送给好友/群
└─ 分享海报 → 生成海报 → 保存到相册
    ↓
好友打开小程序（携带 inviter_id）
    ↓
好友完成首次自查
    ↓
双方各获得1次免费报告
```
